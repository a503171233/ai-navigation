## 一、部署前准备

### 1.1 环境要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Linux（CentOS / Ubuntu / Debian 均可） |
| Web 服务器 | Nginx 或 Apache |
| PHP | **8.0 及以上**（推荐 8.1 / 8.2） |
| MySQL | 5.6 / 5.7 / 8.0 |
| 磁盘 | 建议预留 10GB+（存放安装包/更新包） |

### 1.2 PHP 必需扩展

在宝塔面板「软件商店 → PHP 版本 → 设置 → 安装扩展」中确保已安装：

- `pdo_mysql`
- `openssl`
- `mbstring`
- `fileinfo`
- `zip`
- `curl`
- `bcmath`（建议安装）

检查方法（宝塔「文件」中新建 `/www/wwwroot/tmpinfo.php` 并访问，或 SSH 执行）：

```bash
php -m | grep -E "pdo_mysql|openssl|mbstring|fileinfo|zip|curl"
```

> 若缺少扩展，接口会返回 `5000 数据库连接失败` 或签名/上传功能异常。

## 二、获取部署包并解压上传

部署包：`dcai_auth_v1.0.0_bt.zip`（Linux 通用包，已剔除本机开发配置、密钥与测试文件，直接部署到宝塔即可）。

1. 方式一（宝塔面板界面）：宝塔 →「文件」→ 进入 `/www/wwwroot/` →「上传」选择部署包 → 上传完成后右键该 ZIP「解压」，得到 `/www/wwwroot/dcai_auth/`；
2. 方式二（SSH）：

```bash
cd /www/wwwroot
unzip dcai_auth_v1.0.0_bt.zip
```

部署包解压后的目录结构：

```
/www/wwwroot/dcai_auth/
├── public/          # Web 根目录（站点运行目录）
├── api/             # 对外 API
├── core/            # 核心库
├── service/         # 服务层
├── config/          # 配置目录（部署包仅含 config.sample.php 样例）
├── storage/         # 上传包/日志/缓存（内置目录骨架）
├── install/         # 安装向导（安装完成后删除）
├── sdk/             # 客户端 SDK（不含本地配置）
├── cron/            # 定时任务
├── modules/         # 模块扩展占位目录
└── docs/            # 本搭建教程
```

> 部署包**不含** `config/config.php`（本机密钥）、`sdk/dcai_config.php`（本机授权配置）等敏感文件，到服务器后由安装向导全新生成，避免旧机器密钥泄露与数据串号。

**目录权限**（宝塔「文件 → 权限」设置，属主 `www:www`）：

```bash
chown -R www:www /www/wwwroot/dcai_auth
chmod -R 755 /www/wwwroot/dcai_auth
chmod -R 775 /www/wwwroot/dcai_auth/storage
chmod -R 755 /www/wwwroot/dcai_auth/config
```

> ⚠️ 若服务器上存在旧的 `config/config.php`（例如从本机直接复制），请先删除它，让安装向导重新生成；否则会沿用旧机器的密钥。

## 三、创建数据库

1. 进入宝塔面板 →「数据库」→「添加数据库」；
2. 数据库名建议：`dcai_auth`，编码选 **utf8mb4**，访问权限 `localhost`；
3. 创建一个**专用账号**（例如 `dcai_user`，密码用强随机串），并授权该数据库；
4. 记录数据库名 / 用户名 / 密码，安装向导会用到。

> 表结构无需手工创建，安装向导会自动导入 `install/schema.sql`（20 张表：产品、授权码、实例、命令、弹窗、更新、远程模块、买家、商城订单、日志、系统升级等）。
> 若服务器数据库已存在旧版（V1.0）结构，安装向导的「升级」模式会幂等补齐新表/新字段（买家 buyerrs、订单 orders、产品售卖字段、授权码永久授权等）。

## 四、创建站点（安装阶段）

> ⚠️ **重要**：安装向导位于项目根目录的 `install/` 下，而系统运行入口在 `public/`。因此分两个阶段部署：
> **阶段一**：站点根目录指向项目根目录 → 运行安装向导；
> **阶段二**：安装完成后把站点根目录切到 `public/` 并配置伪静态。

1. 宝塔面板 →「网站」→「添加站点」；
2. 填写域名（如 `auth.example.com`）；
3. **根目录选择项目根目录**：`/www/wwwroot/dcai_auth`（先不要选 public）；
4. PHP 版本选 **PHP-8.2**（或其他 8.x）；
5. 创建完成后，在「网站 → 设置 → 反向代理/伪静态」暂时不配置（安装阶段直接访问即可）。

## 五、运行安装向导

浏览器访问：

```
http://auth.example.com/install/index.php
```

按向导操作：

1. **环境检测**：确认所有项为 ✓（PHP 版本、扩展、目录可写）；
2. **数据库与管理员配置**：
   - 数据库主机：`127.0.0.1`，端口 `3306`
   - 数据库名 / 用户名 / 密码：填写第三步创建的信息
   - 系统访问地址：填写对外域名，如 `http://auth.example.com`（**不要带结尾斜杠**；此地址会用于生成 SDK 更新包的下载 URL，务必正确）
   - 设置超级管理员账号密码
3. 点击「开始安装」，成功后会生成：
   - `config/config.php`（含 RSA 密钥对、AES 密钥、app_secret）
   - 数据库 16 张表
   - 超级管理员账号

> 若提示「openssl 密钥生成失败」，属正常现象少见的 PHP 编译问题，可 SSH 确认 `/etc/ssl/openssl.cnf` 存在即可。

## 六、切换站点根目录并配置伪静态

### 6.1 切换根目录

宝塔 →「网站」→ 对应站点 →「设置」→「网站目录」：

- **运行目录**：`/www/wwwroot/dcai_auth/public`
- 保存后，**删除项目中的 `install/` 目录**（安全要求，必须删除）。

### 6.2 配置伪静态

宝塔 →「网站」→「设置」→「伪静态」，选择 Nginx 并填入：

```nginx
location / {
    try_files $uri $uri/ /index.php?$query_string;
}

# 静态资源直接返回（可选，上面的规则已兼容）
location ~* \.(css|js|png|jpg|gif|svg|ico|woff2?|ttf|eot)$ {
    expires 7d;
    access_log off;
}
```

规则说明：

- 站点根目录为 `public/`，其中的静态文件（`/assets/...`）由 Nginx 直接服务；
- 请求 `/api/v1/xxx` 时，`public/` 下不存在对应文件，`try_files` 回退到 `/index.php`（即 `public/index.php` 前端控制器），再由前端控制器转发给 `api/index.php`；
- 后台页面 `/admin/*.php` 为真实文件，正常直接执行。

### 6.3 关闭防跨站限制（关键）

宝塔默认开启「防跨站攻击」（open_basedir），若站点根目录是 `public/`，PHP 将无法读取 `public/` 之外的 `core/`、`api/`、`config/`、`storage/`，会导致**所有页面白屏 / 接口 500**。

设置方法：宝塔 →「网站」→ 站点「设置」→「配置文件」，将 `open_basedir` 指向**项目根目录**：

```nginx
# 原（错误）：
# fastcgi_param PHP_ADMIN_VALUE "open_basedir=/www/wwwroot/dcai_auth/public/:/tmp/";

# 改为（正确）：
fastcgi_param PHP_ADMIN_VALUE "open_basedir=/www/wwwroot/dcai_auth/:/tmp/";
```

## 七、PHP 扩展与运行参数调整

宝塔 →「软件商店」→ 对应 PHP 版本 →「配置修改」，调整以下参数：

| 参数 | 建议值 | 说明 |
|---|---|---|
| `upload_max_filesize` | `256M` | 允许上传 200MB 安装包/更新包 |
| `post_max_size` | `256M` | 必须 ≥ upload_max_filesize |
| `max_execution_time` | `120` | 解压大安装包 |
| `max_input_time` | `120` | — |
| `memory_limit` | `256M` | 解压/沙箱运行内存 |
| `error_log` | 默认即可 | 排障时查看 |

修改后**重启 PHP**（宝塔 → 软件商店 → PHP → 重启）。

## 八、目录权限与安全加固

### 8.1 权限

```bash
cd /www/wwwroot/dcai_auth
chown -R www:www storage config
chmod -R 755 storage config
chmod 600 config/config.php        # 含 RSA 私钥与 app_secret
```

> `config.php` 属主必须是 `www`（PHP 运行用户），否则 PHP 读不到配置。

### 8.2 删除安装向导

```bash
rm -rf /www/wwwroot/dcai_auth/install
```

> 部署包已不含测试脚本，无需再清理。`install/` 仅用于首次安装向导；若日后系统升级需要同步数据库结构，可临时恢复 `install/` 并访问 `/install/index.php`，点击「升级数据库结构」（幂等执行全部 `CREATE TABLE IF NOT EXISTS`），完成后务必再次删除该目录。

### 8.3 关闭调试模式

安装向导生成的 `config/config.php` 中 `debug` 已为 `false`，请确认：

```php
'app' => ['debug' => false, ...],
```

### 8.4 启用 HTTPS（强烈建议）

宝塔 →「网站」→「SSL」→ 申请 Let's Encrypt 证书并强制 HTTPS。

- HTTPS 生效后，务必把「系统设置」中的访问地址同步为 `https://auth.example.com`，否则 SDK 更新包下载地址仍是 http（或不带端口）。

### 8.5 其他建议

- 后台默认路径 `/admin/`，建议通过 Nginx `location` 增加 IP 白名单或访问密码；
- 定时备份数据库与 `storage/`（备份脚本见下方定时任务）；
- 防火墙仅放行 80/443；
- 定期到「日志管理」查看授权验证、操作、模块调用日志。

### 8.6 系统在线升级（OTA）

系统内置「系统升级」后台（菜单：**系统升级**），可在不接触服务器的情况下在线更新服务端代码：

- **上传升级包**：上传 `zip` 格式升级包（大小上限 200MB，存放到 `storage/updates/`），系统会校验：根目录格式、大小、扩展名、zip 炸弹（解压层级/数量/体积）、清单文件 `update.json` 与目标版本号；
- **发布 / 暂停**：升级包上传后处于"待发布"状态，可在后台发布或暂停，对外下载接口受发布状态控制；
- **应用 / 回滚**：点击「应用」后系统自动备份被替换文件，逐文件替换 / 删除 / 执行迁移脚本，成功后把新版本号（`app.version`）写入 `config/config.php` 并标记完成；**任一步失败自动回滚**，恢复原文件、清理新增文件并标记「失败」；
- **版本管理**：当前系统版本显示于升级页顶部，升级包要求目标版本号大于当前版本（语义化比较校验）。

运维注意事项：

- OTA 应用前系统会备份被覆盖文件到 `storage/`，请确保 `storage/updates/`、`storage/logs/` 目录可写（属主 `www`）；
- 建议在应用升级前先备份数据库（见第九节备份任务）；
- 客户端 SDK 的在线更新（`sdk/dcai_updater.php`）属于"被授权程序的更新"，与本系统自身的 OTA **相互独立**，互不干扰。

## 九、配置定时任务

系统依赖定时任务完成「离线实例判定」「命令超时标记」「限流清理」。

宝塔 →「计划任务」→ 添加任务：

- 任务类型：**Shell 脚本**
- 执行周期：**每分钟**
- 脚本内容：

```bash
php /www/wwwroot/dcai_auth/cron/offline.php >> /www/wwwroot/dcai_auth/storage/logs/cron.log 2>&1
```

（可选）每日备份数据库，再添加一条任务，周期「每天」：

```bash
mysqldump -udcai_user -p'数据库密码' dcai_auth | gzip > /www/backup/dcai_auth_$(date +%Y%m%d).sql.gz
```

## 十、部署验证

### 10.1 后台

1. 访问 `https://auth.example.com/admin/login.php`，使用安装向导创建的管理员登录；
2. 检查「仪表盘」统计是否正常显示。

### 10.2 对外 API

```bash
# 未签名请求应返回 1001/1002 类错误（说明路由与签名框架生效）
curl -X POST https://auth.example.com/api/v1/auth/verify -d '{}'
# 期望输出：{"code":1002,"msg":"签名校验失败","data":null}
```

### 10.3 SDK 客户端（被授权程序）

1. 复制 `sdk/` 目录到被授权程序项目中；
2. 将 `sdk/dcai_config.sample.php` 复制为 `sdk/dcai_config.php`，修改：
   - `server_url` → `https://auth.example.com/api/v1/`
   - `product_code` → 后台产品编码
   - `app_secret` → 「系统设置」中查看
   - `license_key` → 后台生成的授权码
   - `rsa_public_key` → 「系统设置」中复制
3. 集成到程序入口后，确认后台「实例管理」出现新实例且状态为在线。

### 10.4 系统在线升级（OTA）

1. 后台菜单进入「**系统升级**」，确认页面顶部显示当前系统版本（来自 `config/config.php` 的 `app.version`）；
2. 任选一个合法的 `zip` 升级包上传 → 状态变为「待发布」→ 点击「发布」→ 「应用」；
3. 应用成功后系统版本号自动更新，`storage/updates/` 中保留升级包；可再次「应用」同版本号高一级的升级包验证版本号持续递增；
4. 可故意改动升级包（如删除 `update.json`）验证上传被拦截、应用失败可自动回滚（页面标记「失败」，代码与配置均恢复原状）。

## 十一、常见问题排查（FAQ）

| 现象 | 原因与解决 |
|---|---|
| 所有页面白屏/接口返回 500 | ① 检查 `config/config.php` 是否存在且数据库连接正确；② **open_basedir 未放开**（见 6.3）；③ PHP 缺少扩展 |
| 后台能开但 `/api/` 全部 404 | 伪静态未生效，检查站点根目录是否为 `public/` 且已填入 6.2 的规则 |
| 返回 `5000 数据库连接失败` | `config.php` 中 db 配置错误（主机/端口/库名/账号/密码） |
| 上传大安装包报错/超时 | 检查 7 中 `upload_max_filesize`、`post_max_size`、`max_execution_time` 并重启 PHP |
| 授权码导出 CSV 乱码 | 已内置 UTF-8 BOM，用 Excel 打开正常；请勿用记事本另存为 ANSI |
| SDK 提示网络错误/无法连接 | ① `server_url` 填错；② 服务器未放行 HTTPS；③ 防火墙拦截 |
| SDK 更新包下载 URL 不正确 | 站点根目录/系统访问地址配置不对，检查 `config/config.php` 的 `app.base_url` |
| 实例一直离线 | ① 心跳未配置（SDK `runHooks()`/定时心跳未接入）；② `heartbeat_threshold` 阈值过小；③ cron 未运行 |
| 验证接口提示 `1004 请求过于频繁` | 同一授权码/IP 1 分钟内请求超限（默认 verify 30 次/分钟），可在「系统设置」调高 |
| 后台提示 CSRF 失败 | 服务器时间不准导致会话异常，校准时间（`ntpdate ntp.aliyun.com`） |
| 模块沙箱执行报「无法启动沙箱子进程」 | **V1.3 起已自动降级**：系统检测到 `proc_open` 被禁用（宝塔默认 `disable_functions`）时会切换到进程内沙箱继续执行，模块功能不受影响；如仍失败，检查 PHP 可执行文件路径（`PHP_BINARY`） |
| 远程模块执行超时（返回 `5000 模块执行超时`） | 模块代码存在死循环或超长耗时；进程内沙箱依赖 tick 机制中断（默认 ≤5 秒），含空循环体的死循环会走 `set_time_limit` 兜底；请优化模块代码 |
| 「系统升级」上传被拒绝 | 升级包必须为 `zip`、≤200MB、根目录为文件（无单层包裹目录）、含 `update.json` 且目标版本号大于当前版本 |
| 「系统升级」应用后提示失败（红色） | 系统已自动回滚原文件，请先备份并核对升级包内文件路径/迁移脚本，再重新制作升级包 |
| 升级后系统版本号未变化 | 检查 `config/config.php` 是否可写（属主 `www`）；OTA 成功后由系统自动写回 `app.version` |

### 服务器时间校准

授权系统依赖时间戳签名校验（默认允许 ±300 秒偏差），务必保证服务器时间准确：

```bash
# CentOS
yum install -y ntpdate && ntpdate ntp.aliyun.com
# Ubuntu / Debian
apt install -y ntpdate && ntpdate ntp.aliyun.com
```

## 十二、附录：Apache 部署参考

若使用宝塔的 Apache 站点，除根目录指向 `public/` 外，需在 `public/` 下创建 `.htaccess`：

```apache
<IfModule mod_rewrite.c>
    RewriteEngine On
    RewriteBase /

    # 静态文件直接服务
    RewriteCond %{REQUEST_FILENAME} -f [OR]
    RewriteCond %{REQUEST_FILENAME} -d
    RewriteRule ^ - [L]

    # API 与页面统一入口
    RewriteRule ^ index.php [L]
</IfModule>
```

并确保 Apache 的 `open_basedir` 同样放开到项目根目录（站点根目录的上级）。

## 附：部署流程速查

```bash
# 1. 上传部署包并解压到 /www/wwwroot/dcai_auth，属主改为 www
cd /www/wwwroot
unzip dcai_auth_v1.0.0_bt.zip
```
